# Daily sales report by SKU

Скрипт обрабатывает выгрузку заказов `sales.csv` и формирует `daily_by_sku.csv` с агрегатами по артикулу и дате заказа.

## Требования

- Python 3.10 или новее.
- Дополнительные Python-библиотеки не нужны: используются стандартные `csv`, `collections`, `dataclasses`, `datetime`, `pathlib` и `unittest`.

## Запуск

1. Скопируйте исходную выгрузку в корень проекта и назовите файл `sales.csv`.
2. Откройте терминал в корне проекта.
3. Выполните команду:

   ```bash
   python main.py
   ```

   В Windows также можно использовать `py main.py`, а в macOS/Linux — `python3 main.py`.
4. Результат появится рядом со скриптом в файле `daily_by_sku.csv`.

## Формат результата

Файл `daily_by_sku.csv` содержит четыре колонки:

- `sku` — артикул;
- `order_date` — дата заказа в формате `YYYY-MM-DD`;
- `orders` — количество уникальных заказов для артикула за день, включая отменённые;
- `revenue` — сумма `quantity × price` только по строкам со статусом `delivered`.

Строки отсортированы сначала по `sku`, затем по `order_date`.

## Очистка исходных данных

В приложенной выгрузке было 13 858 строк. Найдено 60 повторов полных строк; после удаления дублей осталось 13 798 уникальных строк.

При чтении данных скрипт удаляет пробелы по краям текстовых полей и приводит статусы к нижнему регистру. Вариант `canceled` нормализуется до `cancelled`. Таким образом, регистр и пробелы не создают отдельные значения статуса.

Найдено 4 пустых значения `quantity`; все они относятся к отменённым заказам. Эти строки сохраняются и учитываются в `orders`, но не участвуют в выручке. Если `quantity` отсутствует у выкупленного заказа, скрипт завершает работу с понятной ошибкой, поскольку для расчёта выручки такого значения недостаточно.

Полные дубли удаляются после нормализации. Уникальность заказа при подсчёте `orders` дополнительно обеспечивается множеством `order_id` внутри каждой группы `sku` + `order_date`.

## Проверка результата

Для приложенного файла получены следующие контрольные показатели:

| Проверка | Результат |
|---|---:|
| Строк в исходной выгрузке | 13 858 |
| Удалено полных дублей | 60 |
| Уникальных строк после очистки | 13 798 |
| Строк со статусом `delivered` после очистки | 12 047 |
| Строк со статусом `cancelled` после очистки | 1 751 |
| Строк в итоговом отчёте (пары SKU-день) | 631 |
| Сумма `orders` по отчёту | 13 798 |
| Сумма `revenue` по отчёту | 10 276 540 руб. |

Дополнительно выполнены автоматические тесты на нормализацию статусов, удаление дублей, учёт отменённых заказов, проверку отсутствующего `quantity` у выкупленного заказа и сортировку результата. Тесты запускаются командой:

```bash
python -m unittest discover -s tests -v
```

Ручная проверка контрольной группы: `sku = UYT-0010`, `order_date = 2026-08-21` — один выкупленный заказ с `quantity = 1` и `price = 890`; в отчёте для этой пары должно быть `orders = 1`, `revenue = 890`.

## Ограничения

- Скрипт ожидает CSV с заголовками `order_id`, `order_date`, `sku`, `quantity`, `price`, `status` и датами `YYYY-MM-DD`.
- `quantity` и `price` должны быть целыми числами; пустой `quantity` допустим только у отменённого заказа.
- Неизвестный статус, некорректная дата или некорректное числовое значение приводят к остановке с сообщением об ошибке. Скрипт не пытается автоматически угадывать смысл неизвестных значений.
